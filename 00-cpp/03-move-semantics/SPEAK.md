## Q1. `std::move` 는 무엇을 하나요? `[목표 60초]`

**(결론)**
std::move는 이름과 달리 이동을 직접 하지는 않습니다. 단지 인자로 들어온 lvalue 변수에 &&를 붙여 이동 생성자가 있을 경우 이동을 할 수 있도록 준비를 시켜줍니다.
<!-- 이름에 속으면 안 되는 자리다. 한 문장으로. -->

**(이유)**
받는 클래스 형의 이동 생성자 유무에 따라 실제 이동을 할지 결정됩니다. 그리고 복사 생성자, 복사 대입 연산자, 소멸자 중 하나라도 사용자 정의가 되어 있는 경우 기본 이동 생성자를 만들지 않기 때문에 복사 생성을 진행합니다.

**(사례)**
Payload에 이동 생성자가 없는 상태에서 Payload b = std::move(a)를 해봤습니다. 복사가 1회 세어졌고, 옮긴 뒤에도 a.Data의 길이는 64로 그대로였습니다. 이동 생성자가 없어도 우측값은 const& 매개변수에 바인딩될 수 있어서 복사 생성자가 후보로 남습니다. 그래서 오류가 안 나고 조용히 복사로 떨어집니다.

## Q2. `auto` 를 쓸 때 주의할 점은? `[목표 60초]`

**(결론)**
auto 는 추론할 때 참조와 const 를 떼어내기 때문에, 그냥 auto 로 받으면 의도하지 않은 복사가 생깁니다.

**(이유)**
참조와 const를 떼어내면 레퍼런스로 받는게 아닌 객체를 생성하여 받기 때문에 복사가 됩니다. 객체를 레퍼런스로 받으면서 원본을 건드리지 않을 때 const auto&로 사용하면 됩니다.

**(사례)**
const &를 붙이지 않는 auto p = GetConstRef()은 복사가 1번, for(auto e : v)에서는 객체를 받을 때 복사가 3번 일어났습니다. const auto& p = GetConstRef(), for(const auto& e : v)처럼 const &를 붙여주면 복사나 이동이 0번으로 원본 객체를 그대로 쓸 수 있었습니다.

## Q3. 람다를 쓸 때 조심하는 것이 있나요? `[목표 60~90초]`

**(결론)**
람다의 변수 캡처 방식에 값과 레퍼런스 방식이 있습니다. 레퍼런스 방식으로 받은 객체가 사용되기 전에 제거되면 사용할 때 댕글링 포인터가 될 수 있습니다.
<!-- 캡처 방식과 수명 -->

**(이유)**
람다는 이름 없는 클래스고 캡처에 있는 변수가 멤버가 됩니다. 레퍼런스로 받는 멤버는 계속 같은 곳을 가리키고 있기 때문에 미리 제거가 되면 사용할 때 없는 객체를 가리키고 있을 수 있습니다.

**(사례)**
함수 내부에서 지역 객체를 만들어 레퍼런스로 캡처한 람다를 밖에서 사용해봤습니다. 함수를 빠져나온 시점에 지역 객체는 이미 소멸해 있었고 밖에서 두 번 호출할 동안 값이 달랐습니다. 대신에 값으로 캡처한 같은 람다에서는 의도했던 값이 나왔습니다. 이미 없어진 객체에 대해서 접근할 때 크래시가 나야 잘못 사용된 부분을 확인할 수 있지만 크래시가 발생하지 않아 잘못된 값이 사용될 수 있음에도 불구하고 정상적으로 작동을 하고 있었습니다.
